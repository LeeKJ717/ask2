2. 확정된 결정

  1. 작업 폴더는 윈도우 노트북 Desktop\daily3\obese2. 문서 산출물은 Downloads 폴더에도 자동으로 넣는다.
  2. 모든 조판 관련 데이터는 db/obese2.db(SQLite)에도 저장한다. 원고, 그림 원본·데이터·스크립트, 표, 참고문헌, 목차, 규칙, 검증 목록을 담는다.
  3. 파일명에 언더바를 쓰지 않고, 버전을 붙인다(예: 01장-v1.md).
  4. 한자어는 한국어 발음으로 쓴다. 새 용어는 처음 나올 때 full name을 쓴다.
  5. 모든 그림·표에 번호와 제목. 정량 자료가 아닌 그림은 “개념도”라고 밝힌다. 모든 그림은 숫자 읽는 법과 해석 문단을 붙인다.
  6. 그림은 컬러판과 흑백판(-흑백.png) 한 쌍으로 만든다.
  7. 근거 없는 숫자를 만들지 않는다. 기억에 의존한 서지·수치는 refs/tocheck.md에 넣고 원문 대조 후 지운다.
  8. 책 순서: 1권 → 2권 → 3권 순으로 쓰되 2권은 1권 3·4·5장과 맞물린다(각 장의 “2권 연결” 줄).

5. DB 사용법 (db/obese2.db)

테이블: meta, files(모든 파일을 경로·해시·본문/바이너리로 보관), chapters, figures, tables_, refs, tocheck, toc, rules, decisions, status.

  • 갱신: python tools/dbload.py (프로젝트 루트에서 실행. 파일을 읽어 변경분을 반영하고 해시를 기록한다)
  • 복원: python tools/dbexport.py 출력폴더 (DB에서 전체 폴더 트리를 되살린다)
  • 조회 예: sqlite3 db/obese2.db "select vol,ch,title,length(md) from chapters"

원고를 고치면 마크다운 파일을 고친 뒤 dbload.py를 다시 실행한다. DB가 원본이 아니라 파일과 DB가 서로 복제본이며, 변경 이력은 git으로 기록한다(git init 후 커밋).

6. 장 집필 템플릿 (1~3장에서 쓴 형식)

  1. 부 제목, 장 제목.
  2. 인용 상자 “이 장의 출발점”: 앞 장에서 이어지는 질문, 2권 연결 위치.
  3. 절 구성: 발견의 이야기(인물·시대·실패·전환점) → 핵심 논문(실험 배경과 과정, 결과, 해석) → 그림·표 → 다음 장으로 가는 질문.
  4. 그림: **그림 N-M. 제목.** 설명 + 이미지 링크 + 본문에 읽는 법과 해석.
  5. 표: **표 N-M. 제목.** + 마크다운 표 + 읽는 법. 한 쪽 안에 들어가야 한다.
  6. 장 끝 #### 참고문헌 APA 7th.

7. 그림 제작

  • 데이터 그래프·간단 도표: matplotlib. 폰트 Malgun Gothic(없으면 Noto Sans CJK KR), 폭 6.93인치(176mm), 300dpi, 컬러·흑백 쌍. 예: figures/scripts/fig1-1.py
  • 생물 도해·회로도: figlib.py(좌표 SVG). 글자 22단위 이상, 겹침·넘침 검사 F.report()가 0건이어야 한다. 렌더링은 cairosvg(pip install cairosvg --break-system-packages). 예: figures/scripts/fig3-1.py
  • 스크립트는 python3 -I 로 실행한다.
  • 생물 그림은 교과서식 도해(지시선 라벨, 정상과 병변 대비, 순환 경로)로 그린다. 세포·분자 그림에서는 개체에서 세포, 소기관, 핵, 유전자, 분자로 내려가는 순서를 따른다.

8. 검증 대기와 보완 목록

상세는 refs/tocheck.md. 요약:

  • 1~3장의 모든 DOI·쪽·저자 목록은 기억 기반이라 Crossref로 대조해야 한다. Crossref는 한 번에 3~4건만 병렬 호출한다(그 이상은 제한에 걸린다). PubMed는 이 환경에서 차단된다.
  • Bell et al. (1983)은 햄스터 프로글루카곤 논문이다. 사람 유전자를 말하려면 Nature 304:368 계열로 교체한다.
  • STEP 1(−14.9% 대 −2.4%, n=1,961, 68주), SURMOUNT-1(−15.0/−19.5/−20.9% 대 −3.1%, n=2,539, 72주), SCOUT(n=9,804, 위험비 1.16)의 수치를 원문으로 확인한다.
  • 구조 불일치: toc-v5 1장 항목 중 비만 정의(체질량지수)·합병증 절과 그림 1-2(5-HT2B 판막 기전 도해)가 아직 없다. 2장에는 그림 2-2(약물 계보도)가 없다. 현재 그림 1-2는 에너지 수지 개념도이므로 번호 정리가 필요하다.
  • 번역어 통일: GIP는 “포도당 의존성 인슐린 분비 자극 폴리펩타이드”로 통일한다.

9. z840 논문 DB 작업 (obesepharma_db)

  • 위치: ~/obesepharmadb/(스크립트 01search.py, 02pdf.py, 03fulltext.py, run.sh), 로그 ~/obesepharma-v3.log. 사본은 tools/z840pipeline/.
  • 새 DB를 만들면 저장 위치는 dball2(z840 /data/safe/dball2) 규칙을 따른다.
  • 진행: 원래 실행(run.sh)이 전문 수집 단계였고, v3 작업이 보강 4개 축(clinical_named, structure_gpcr, smallmol_agonist, comp_method)을 검색한 뒤 원래 실행이 끝나기를 기다렸다가 오류(ft_status=3)를 되돌려 전문·PDF 단계를 다시 돈다.
  • Europe PMC 일부 PMCID에서 HTTP 500이 나는 것은 서버 쪽 문제다.
  • 끝난 뒤 python3 tools/z840pipeline/reviewdbv1.py 를 z840에서 다시 실행해 review-v1.md 를 만들고 목차의 DB 표를 갱신한다(toc-v6).
  • 3권 GPU 배치표에서 z441의 GPU는 아직 확인하지 못했다.

10. 다음 작업 순서

  1. refs/tocheck.md 의 서지를 Crossref로 대조(1~3장). 병렬 호출은 3~4건씩.
  2. 1권 4장(장이 보내는 신호: 호르몬 지도). 그림 4-1(분비 세포 위치, figlib), 그림 4-2(식후 호르몬 곡선, 개념도로 표기), 표 4-1.
  3. 5장(표적 장기), 이후 3부 6~9장 … 17장. 각 부 끝의 산출물(점검 표)을 만든다.
  4. 1~2장 보완(비만 정의 절, 그림 1-2 재배치, 그림 2-2).
  5. 정식 조판 파이프라인: B5, 왼쪽 20% 여백, 그림·표 전폭, 쪽 하단 쪽번호, 목차 쪽번호, 컬러·흑백 쌍, 표는 두 쪽에 걸치지 않게, 쪽 여백 15% 이하 자동 배치.
  6. 개념 의존성 DB, 과학자 상자, “과학의 최전선” 상자(physic.md 아이디어) 도입 여부 결정.
  7. 표지(펼침면): 쪽수가 정해진 뒤 책등 두께 = 쪽수 × 0.055mm + 0.5mm, 펼침 폭 = 3 + 210 + 책등 + 210 + 3 mm(높이 303mm) 규칙으로 계산.

10-1. PDF 시험본 빌드

  • 명령(프로젝트 루트): python tools/buildpdf.py draft → build/obese2-draft-v1-color.pdf, -bw.pdf. python tools/buildpdf.py handoff → 인계서 PDF.
  • 도구: pandoc, playwright(Chromium), poppler(pdftotext). 쪽 좌우 여백을 0으로 두고 글 요소에만 왼쪽 35.2mm·오른쪽 14mm를 주어 그림·표가 쪽 전체 폭(176mm)을 쓰게 했다.
  • 알려진 한계: ① 그림 캡션이 그림 아래 한 번(대체 텍스트), 위 문단에 한 번 나온다. 캡션 순서와 중복을 정리해야 한다. ② 그림·표가 쪽 끝에서 다음 쪽으로 밀려 아래 여백이 큰 쪽이 생긴다(자동 배치 필요). ③ 참고문헌 글자 크기는 본문보다 1pt 작게(9pt) 처리했다. ④ 장 시작 쪽 번호는 두 번 계산해 목차에 넣는다.

12. 환경 메모

  • 이 클라우드 작업 공간의 셸에서는 NCBI·EBI에 접속할 수 없다(403). WebFetch의 Crossref는 가능하다.
  • 윈도우 노트북 폴더 쓰기는 연결된 폴더(Desktop\daily3, Downloads) 안에서만 된다. 장치에서 git 은 실행할 수 없으므로 사용자가 PowerShell 한 줄로 git init·커밋을 한다.
  • 명령은 한 응답에 한 터미널 분량만 주고, 터미널 이름을 코드 상자 위에 굵게 쓴다.
